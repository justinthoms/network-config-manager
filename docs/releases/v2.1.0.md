## Highlights

### ⬆️ Upgrade NCM from the web UI
From this version on, NCM checks GitHub for new releases and shows a banner to Admins when one is out. A Super Admin opens **user menu → Updates**, reads the release notes and clicks **Upgrade**. The new version is tested on a copy of your database before anything changes, the current version is saved for one-click rollback, and NCM restarts by itself. Your `.env`, keys, database, backups and custom vendor logos are kept.

### 🔎 A much better config viewer
Line numbers, find with a match count (Enter / Shift+Enter, Ctrl+F), `:120` to go to a line, jump to any section (interface, vlan, router …), wrap lines, copy, full screen, older/newer backup buttons and **Compare with previous**. A **Hide secrets** switch (on by default) masks passwords, keys and SNMP communities, so you can share your screen safely.

### 🔍 Config search across every device
New **Search** page: find a VLAN, an IP address, a description or an NTP server in the latest configuration of every device at once. Each match shows its line and section (for example `interface GE1/0/1`); click it to open the config at that line. Export the results to CSV.

### 🛡️ Only allowed commands reach your devices
Health checks and the assistant's live commands run only commands from an allowed list of read-only commands per vendor. Only a Super Admin can allow extra ones, and commands that print the configuration or secrets are always refused.

## Security fixes
- **Viewers no longer see secrets.** Roles without download permission always get configs with passwords, keys and SNMP communities masked: in the viewer, file browser, comparisons, search and dashboard.
- An Admin can no longer reset, disable or change the role of another Admin (or of a Super Admin).
- Fixed script injection through device hostnames, sites and file names in the web UI.
- A saved AI provider key is only ever sent to that provider's own address.
- Downloads are written to the audit log.

## Reliability
- Safe with several worker processes (`--workers N`).
- Database changes are managed with Alembic and applied automatically at start.
- Cloud uploads go through a queue; old failed backup records are cleaned up daily.

## How to upgrade to 2.1.0
2.0.0 does not have the in-app updater yet, so this one upgrade is done by hand. Later versions can be installed from the Updates page.

1. Back up `backend/.env`, `backend/.secret_key`, the database and your backup folder.
2. Get the new code: `git fetch --tags && git checkout v2.1.0` (or download the source archive below and copy it over, keeping `.env` and the database).
3. Install the Python packages: `.venv/bin/pip install -r backend/requirements.txt`
4. Restart NCM: `sudo systemctl restart ncm`. The database is upgraded automatically.

New settings (all optional) are listed in `backend/.env.example` under **Updates**.

The full list of changes is in [CHANGELOG.md](https://github.com/justinthoms/network-config-manager/blob/main/CHANGELOG.md).
